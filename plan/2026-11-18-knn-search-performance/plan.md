## 3. Goal

Cut SQLite-backed DiskANN `knn_search` query latency by making each published generation self-contained per node, so the hot query path stops executing a 3-table join (`diskann_graph_nodes` LEFT JOIN `diskann_entries` LEFT JOIN `diskann_current`) per neighbour target and per scored candidate, and instead performs at most one single-table point read per expanded or scored node, with live-ness decided from retire-maintained per-generation state instead of per-read joins. Success-path results stay identical to baseline on every supported-API state; recall stays identical; work and memory stay bounded; every divergence class is explicitly enumerated rather than discovered mid-delivery.

## 4. Success criteria (all required)

**C1 Equivalence contract, scoped explicitly.** Inherits the 11-16 delivery's relaxed failure-path contract (recorded user decision, plans/2026-11-16 section 3) plus the scope below.
- *Success path (quiescent connection):* for every query where the baseline returns rows and no same-connection write occurs during the operation, the candidate returns the same rowids in the same order with the same distance bits, for all recorded workloads — including churned fixtures in all three retirement phases (pre-import, mid-import, post-publish) and fallback-exercising tight budgets — and the full test suite. Strict.
- *Visit accounting:* total owner visits per query are identical to baseline for the same traversal, so `max_visits` outcomes are unchanged. Under the actual call map (6.2), batch scoring charges rowid+vector (2) per scored candidate and `post_process` decision calls charge 1 each, exactly as HEAD does on the same path; the carry (D5) removes duplicate SQL executions in the final loop, never charges; the retired-state load/validation and identity/state checks charge exactly as HEAD does (zero).
- *Failure path:* where the baseline errors, the candidate also errors, never partial/wrong rows, on supported-API states; single-fault error classes stay stable; coincident-fault ordering may differ (11-16 relaxation).
- *Payload-authority doctrine (explicit):* in Format 5 the published node row is authoritative for `public_rowid`, `state` and adjacency on every route (including the D4 fallback), while **vectors are authoritative in canonical `entries`** for live nodes and in its node row for the frozen root — so `entries.vector` corruption is query-visible exactly as in Format 4, and authority is route-independent. Exactly as `frozen_vector` already is for the root in Format 4, canonical `entries`/`current` remain authoritative for ingest, build, import validation, and publication. Detection of direct shadow-edit corruption is split accordingly: query-time fail-closed applies to published-node rowid/state/adjacency payloads and to every canonical vector read a query actually scores (all reads keep their type/length guards), so `entries.vector` and `entries.retired_revision` tampering on a scored row is query-visible — matching HEAD for the still-current variant and failing closed where HEAD would silently exclude or would serve (per-variant pins in D10) — exactly as in Format 4 for the vector class; canonical `entries` classes the query never reads are caught by the next build/import validation pass **for the versions that pass actually reads** (qualification per round 3: snapshot, build and import validation read only the versions they materialize; trailing retired entries can be skipped, jobs.rs:325-342). The divergence matrix is D10; tests pin every class.
- *Enumerated unsupported-API divergences (explicit, reviewed at the user gate):* states reachable only by direct shadow DML or reentrant host callbacks are out of the strict-equivalence domain and pinned per D10 — most importantly (i) a `current` row deleted or repointed without retirement (baseline excludes the node; ## 5. Scope and non-goals

In scope (deferred DiskANN backend only):

- Query reader reshape: single-table **NodeExpand** and **NodeIdentity** readers plus an **entries-keyed NodeScore** reader (live candidates read canonical vectors by `entry_id`; the root reads its node row); a **format-5-aware three-table fallback reader** replacing the v3 "verbatim HEAD" fallback (D4); exact/projection routes restore HEAD's indexed three-table plan with canonical `e.vector` payload (D4).
- A bounded, budget-charged, operation-local resolved-rowid carry with charge-preserving `rowid()` (D5, D6).
- Import/validation/publish changes to write and validate the denormalized fields, including neighbour-target resolution in worker RAM (T2; `diskann_worker.rs` is in scope).
- Schema/catalog validation updates including the ninth layout's `x_shadow_name` registration and bounded cleanup reclamation; `format_version` 4 -> 5; a dedicated migration surface that does not require the vtab connection (D7, including `lib.rs` registration-slot changes); status JSON format bump (diskann_control.rs).
- Budget/owner arithmetic with the owner envelope and canonical workspace floor held byte-identical and the new carry explicitly charged (D6), import/cleanup per-record byte formulas updated with their boundary tests.
- Debug instrumentation and native CTest host updates; benchmark/accuracy campaign including the churned fixtures; docs.

Non-goals: HNSW path changes; cross-query caches or memos; store-level row-content reuse across reads; proposal C (whole-generation workspace materialization); PQ/float16 storage; changing `beam`, traversal, or tie-breaking (bridge navigation semantics unchanged); multi-id batch statements; new SQL surface beyond the migration scalar; beyond-RAM or cold-disk claims; upstream DiskANN source changes.

## 6. Root cause and evidence

### 6.1 Where the remaining time goes (post-11-16 delivery)

Every graph-route query executes, per expanded node: 1 single-table graph read plus **one 3-table identity join per neighbour target** ([query.rs:617-631](../../vectorlite/src/diskann_deferred/query.rs#L617) `node_sql`; executed per target in `PublishedGraph::neighbors`), and per scored candidate: 1 combined 3-table join + vector projection. At degree 32, L=10 (~10-13 expansions), that is roughly 450-650 multi-table executions per query. The 11-16 cached-plan probe (plans/2026-11-16 section 5.1) measured: 3-table identity join 2.16 us, 3-table join + vector 2.57 us, graph row + vector projection 1.80 us. The join exists only because the published node row stores a bare `entry_id`: resolving the public rowid requires `entries`, and proving live-ness requires `current` ([query.rs:673-725](../../vectorlite/src/diskann_deferred/query.rs#L673) `classify`).

### 6.2 The actual call map (verified against the pinned upstream source in round 3; replaces v3's incorrect map)

- `diskann_core::search` **always** selects the inline-filter machinery: it constructs `InlineFilterSearch::new(knn, None)` ([diskann_core.rs:1564-1571](../../vectorlite/src/diskann_core.rs#L1564)), whose pinned loop always invokes `expand_beam_filtered` ([inline_filter_search.rs:236-242](../../build/benchmarks/diskann-query-latency-20261116/cargo-home/registry/src/index.crates.io-1949cf8c6b5b557f/diskann-0.60.0/src/graph/search/inline_filter_search.rs#L236)) — **whether or not a SQL filter exists**. The `SearchAccessor::expand_beam` (`need_rowid=false`) path exists but is never driven by `search()`. v3's claim that unfiltered scoring runs with `need_rowid=false` was wrong.
- Consequences of `need_rowid=true` expansion: batch scoring reads charge rowid+vector (2 owner visits) per scored candidate exactly as HEAD does on the same path, and the batch reader returns each candidate's rowid inline with its vector; the adapter reports the rowid for charging but does **not** retain it (storing every scored rowid would need scored-candidate capacity, which is unbounded; the carry is instead populated at decision time, D5).
- `post_process` receives `matched_results.into_iter().take(L)` ([inline_filter_search.rs:140-148](../../build/benchmarks/diskann-query-latency-20261116/cargo-home/registry/src/index.crates.io-1949cf8c6b5b557f/diskann-0.60.0/src/graph/search/inline_filter_search.rs#L140)), and the Vec output buffer never reports Full (`size_hint() == None`, [neighbor/mod.rs:280-292](../../build/benchmarks/diskann-query-latency-20261116/cargo-home/registry/src/index.crates.io-1949cf8c6b5b557f/diskann-0.60.0/src/neighbor/mod.rs#L280)), so `Output::post_process` ([diskann_core.rs:1483-1496](../../vectorlite/src/diskann_core.rs#L1483)) calls `decision()` — a charged `rowid()` — on **every supplied candidate, up to L per query**, before the final loop ([diskann_core.rs:1577-1581](../../vectorlite/src/diskann_core.rs#L1577)) takes k. Decision reads are therefore an L-scale term, not k.
- DistanceCache hits inside the filtered expansion call `rowid()` directly on unscored ids ([diskann_core.rs:1019-1023](../../vectorlite/src/diskann_core.rs#L1019)); root/`state()` checks in `start_points()`/`Accessor::new` use the identity path and charge **zero** visits (11-16 D4 map); standalone `rowid()` resolutions charge 1.
- `retire()` already looks up the published and candidate generations for the retired entry (to decrement `eligible_count`, [diskann_store.rs:1240-1288](../../vectorlite/src/diskann_store.rs#L1240)), transactionally with setting `entries.retired_revision` and deleting `current`.
- **Pre-import retirements are invisible to `retire()`:** `import_step` inserts every snapshot node as a state-0 row regardless of eligibility and only increments `eligible_count` when `lookup_live_id(rowid)? == Some(entry)` ([import.rs:288-292](../../vectorlite/src/diskann_deferred/import.rs#L288)). This is why D3 maintains the retired table at import time as well.
- The frozen root (`native_local_id == total_count`) has **no** `snapshot_map` row ([import.rs:160-171](../../vectorlite/src/diskann_deferred/import.rs#L160)); D2 encodes it by sentinel. The root's vector is an exact bit-copy of the medoid's ([diskann_build.rs:874-878](../../vectorlite/src/diskann_build.rs#L874)), so a query near the medoid can supply the root as a rejected candidate (accounted in C3's instrumented bound).
- `native_local_id == snapshot ordinal` and `total_count` == the data-node count were confirmed by all reviewers; they are verified code facts, not assumptions.

### 6.3 Expected effect (estimate, to be replaced by the T0 baseline)

Reader executions fall from ~450-650 multi-table joins to ~(expansions + scored candidates) single-table reads plus a small instrumented setup set, ~L decision reads, and an O(retirements-affecting-this-generation) indexed load that is one count when zero. Estimated p50: 1.5-2.5x at L=10, 2-3x at L=100 on 10k x128; smaller at 3k. The plan gates on measured numbers; if the T0 probe shows the reader share is smaller than modeled, the gate is re-negotiated with the user before implementation instead of being silently lowered.

## 8. Design decisions

**D1 Format-5 published node row.** `diskann_graph_nodes` column order becomes `(generation_id, native_local_id, entry_id, public_rowid, state, neighbors, vector)` — `neighbors` **before** the vector so expansion and identity reads stay in the smallest local-payload prefix. **Locality claim stated honestly (rounds 3-4):** SQLite's local-payload threshold is computed from the usable page size and the record's payload length (roughly 489-1002 bytes on 4 KiB pages for these record shapes) — an approximate, comment-level rationale, not contract. At physical degree 41 the 656-byte adjacency blob can span overflow pages even at 128D, and at 768D it certainly does. The column ordering keeps the identity prefix minimal and avoids walking the vector tail during expansion; the gated 768D no-regression cell and T7 measurements, not any categorical locality claim, protect the outcome.
- state=0 (live data): `entry_id` NOT NULL, `public_rowid` NOT NULL CHECK(public_rowid>=0), **`vector` IS NULL** (v11 lean revision — see section 21; live vectors stay canonical in `diskann_entries`).
- state=2 (frozen root only in Format 5): `entry_id` NULL, `public_rowid` NULL, `vector` blob (the root's vector is the only inline payload; it is not in `entries`).
- Terminology: `graph_nodes.state` (0 live / 2 frozen root) is distinct from `generations.state` (0 staged / 1 published / 2 garbage); cleanup reclaims garbage generations wholesale and does not convert their nodes into frozen nodes.
- Catalog validation, column counts, CHECK constraints, positional import INSERTs, and the schema unit tests are updated together in T1. The WITHOUT ROWID PK and the existing two unique indexes are unchanged; **no** new graph_nodes index is introduced (D4 keeps exact/projection routes on the existing indexes).

**D2 Neighbour slot encoding (frozen before T1).** Each neighbour slot is 16 bytes little-endian: `(native_local_id u64, entry_id u64)`. `entry_id == 0` **iff** `native_local_id == root_local_id` (the frozen root, which has no snapshot-map row); any other zero `entry_id`, or a non-zero `entry_id` on the root slot, is `SQLITE_CORRUPT`. Slot count is bounded by `physical_degree`; `length(neighbors) % 16 == 0` with bound `physical_degree * 16`. `encode_ids`/`decode_ids` extend their duplicate/self/degree/range validation to slots; decode streams ids into the existing `Vec<u64>` so the simultaneous-buffer envelope (16-byte blob copy + 8-byte decoded id) equals the existing `physical_degree * 24` owner term (D6). **Query-time role of the slot's `entry_id` (v12):** it is the canonical scoring key — the reader resolves a scored native id to its `entry_id` through the per-expansion pair cache and reads `entries` by that key (miss path: one `NodeIdentity` read). Eligibility is still decided from the entries row actually read (retired-set membership plus the restored interval rules), never from the slot alone; slot decode also validates import integrity (root sentinel, range, duplicate/self, degree). `PublishedGraph::neighbors()` returns **all** valid target native ids unchanged — retired bridge nodes and the frozen root are never filtered out, because DiskANN traverses retired nodes as navigation bridges (`test_ann_retired_navigation_bridge_and_pending_exclusion`, `test_diskann_retired_navigation_bridge_is_immutable_and_gc_pinned`); filtering would break bridge traversal and C1 on the churned fixtures.

**D3 Retire-maintained per-generation retired-ids table.** New layout `diskann_generation_retired` (WITHOUT ROWID, PK `(generation_id, entry_id)`), maintained at **both** write sites:
1. **`import_step`:** whenever a state-0 node has `!eligible_now` ([import.rs:288-292](../../vectorlite/src/diskann_deferred/import.rs#L288)), insert (generation_id, entry_id) in the same import transaction, via a chunk-scoped `jobs::LoopStatement` finalized before the step returns. This covers pre-import and mid-import retirements that `retire()` could not see.
2. **`retire():** insert one row per affected published/candidate generation inside its existing transaction (the loop at [diskann_store.rs:1240-1288](../../vectorlite/src/diskann_store.rs#L1240) already looks up exactly those generations to decrement `eligible_count`). The insert is a **per-use, non-retained writer slot** (outside `retains_statement`'s retained range, per the 11-17 carrier-assertion history), which T2's writer-budget boundary tests cover; the load statement on the query side is admitted through the reader allowance (D6).
- **Exact invariant:** for every generation whose import has completed **and that has not begun reclamation**, `COUNT(*) FROM diskann_generation_retired WHERE generation_id=?1 == total_count - eligible_count` (both sides count data nodes only; the frozen root sits at ordinal `total_count`, outside both). Bounded cleanup intentionally destroys the invariant for a garbage generation mid-reclaim, so the invariant is asserted only while the generation is staged/published. The import validation pass and publication assert it; a mid-build supported UPDATE/DELETE moves both sides together. The invariant's detection value is **count-changing** tampering with the retired table or the generation counters (round-3 scoping: a balanced substitution that swaps one retired id for another preserves both sides and is **not** detected by the count; it is enumerated in D10 as an accepted limitation, with the next build/import validation reading the versions it materializes).
- **Operation start (graph route only, by design):** one indexed count; round-3 note: the count itself examines all retired members before an oversized set falls back, so T7 records its cost on a large retired population. Mismatch -> `SQLITE_CORRUPT`. Zero -> no further eligibility reads. Otherwise load `SELECT entry_id ... ORDER BY entry_id` into a sorted owned `Vec<u64>` — examined rows are exactly the members (no `entries` scan anywhere), bytes are exactly `count * 8` plus the load statement's measured `MEMUSED`, admitted from the **same reader-allowance cursor** as the node readers; oversized -> the whole query falls back to the D4 three-table reader so no eligibility rule weakens at any budget. **The exact routes deliberately never load the invariant or the set** — they keep `current`-based eligibility exactly as today; a future implementer must not "complete" them with the count check.
- **Mid-operation mutation detector (rounds 4-6):** capture **two** stamps immediately after the metadata anchor steps to Row and before any other operation read — reading `changes_before = sqlite3_total_changes64` (a pure in-memory field read during which no host callback can fire) immediately **before** stepping the schema-stamp statement, so the counter covers the stamp statement's own execution window; the accurate guarantee boundary is the **completed captures**: no observed change between the completed captures and result acceptance (a write landing between the anchor's open and the completed captures is absorbed into the operation's snapshot and enumerated in D10 row 6) and verify both immediately before `knn()` returns Ok (after projection and reader finalization), so every route — graph, exact, fallback, projection — is covered: (1) `sqlite3_total_changes64`, which every same-connection DML moves; and (2) a **shadow-schema stamp** — `(COUNT(*), sum(rootpage))` over the nine shadow-table names read from the vtab schema's `sqlite_schema` catalog in one transient read-only statement (implementation guidance: filter `type='table' AND name COLLATE NOCASE IN (?1..?9)` — the collation attaches unambiguously to the name comparison, and SQLite resolves table names ASCII case-insensitively — over the schema-qualified catalog, matching the existing qualified-name discipline so temp/main/attached are never confused). Either stamp moving fails closed with `SQLITE_BUSY` (D10 class R). **The guarantee is precise (round-6 narrowing):** the stamp catches shadow-object-relocating changes — rename away (count drops), rename-in of a pre-made substitute (its live rootpage enters the sum), drop (count drops; unreachable mid-operation anyway because `OP_Destroy` refuses under the anchor's live VM), and CTAS-recreation (a fresh root page enters the sum, since the renamed-away original keeps its pages and `OP_Destroy` cannot free them mid-operation) — and the change counter catches all DML. It does **not** catch root-preserving definition changes (column renames, `ADD COLUMN ... GENERATED ... VIRTUAL`) or permutations preserving the aggregate rootpage sum; those classes are enumerated undetected divergences in D10 row 6 with pinned probes of their documented outcomes (fail-closed via column-mismatch reprepare or the eligible-count check, or documented divergence with substituted values or stale/retired published rows). Benign unrelated DDL leaves the stamp unchanged and reprepares transparently exactly as HEAD does (the transparent-reprepare test's success branch is preserved); the round-4 rename+CTAS counterexample is caught and pinned by a deterministic probe (T6).
- The retired count/load and its validation charge zero visits (state checks charge 0 exactly as HEAD).

**D4 Query reader reshape.** Three single-table node reader shapes over `diskann_graph_nodes`: **NodeExpand** (identity columns + `neighbors`, no vector), **NodeScore** (v11: an `entries` point read by `entry_id` projecting `entry_id, public_rowid, created_revision, retired_revision, vector` — the rowid and vector charges of `need_rowid=true` expansion are unchanged, and the root is served from its node row), and **NodeIdentity** (identity columns only — no vector, no neighbors — the smallest prefix read, used for `state()`, root checks, carry misses, and `post_process` decision reads).
- **Fallback reader (round-3 correction, replacing v3's "verbatim HEAD" wording): a format-5-aware three-table reader** with HEAD's join shape (`graph_nodes` keyed by native_local_id, LEFT-joined to `entries` and `current`) but v5 role semantics: a live node's `vector` must be NULL and the root's must be a valid blob — HEAD's original role rule, now consistent with D1 — with the payload projected from canonical `e.vector` for live nodes and `n.vector` for the root; eligibility via the per-read `current` join using HEAD's current-based classification, with the retirement-consistency checks **restored** so the v12/v13 scored-row corruption guarantee holds on this route too: a still-current entry carrying any `retired_revision` is `SQLITE_CORRUPT` (HEAD's original rule), interval ordering is validated (created >= 1, created <= snapshot source revision, retired > created, retired <= metadata revision), and the fallback keeps **HEAD's exact `classify` asymmetry** (it cannot use retired-set membership): a **non-current** entry is `Deleted`, with interval bounds validated only when a retirement revision is present — so a shadow-deleted `current` row without a retirement revision is excluded, not corrupt (D10 row 3) — while a **still-current** entry carrying any retirement revision is `SQLITE_CORRUPT` (D10 row 4); and the vector projection reads canonical `e.vector` (v11: live vectors are no longer inline; the root reads `n.vector`), and rowids resolve from the **published** `n.public_rowid` (the join's `e.public_rowid`, if projected at all, is validation-only), so payload authority is route-independent — on supported states the published copy equals the canonical copy (import-validated), giving results and distance bits identical to HEAD, which the churned tight-budget differential cells gate end to end. Byte-verbatim reuse of HEAD's SQL is not possible because the column names and the `public_rowid` projection changed; the role rule itself is HEAD's original again (live -> NULL, root -> blob).
- Exact/projection/IN routes restore HEAD's indexed three-table `eligible_sql` shape (`graph_nodes n JOIN current c` plus `entries e` for the canonical payload; current PK + the existing `UNIQUE(generation_id, entry_id)` keep O(log N); eligibility via `current` exactly as today), because live vectors are no longer inline. Every read keeps its blob type/length guards and Row-then-Done discipline; no store-level row-content reuse across reads.

**D5 Operation-local resolved-rowid carry (charge-preserving; population restricted to post-processing).** One carry of at most `effective L + 1` entries of `(native_local_id, Option<public_rowid>)`, implemented as a **fixed-capacity ring buffer that overwrites the oldest slot when full** (round-3 corrections from both carbon and sol). Its population sites are restricted exactly: **only** the `decision()`-time NodeIdentity reads performed by `Output::post_process` insert into the carry; every other `rowid()` caller (DistanceCache hits during expansion, `start_point_distances`, root checks) consults the carry but never populates it — so pre-post-process calls cannot wrap the ring. `post_process` supplies at most `take(L)` candidates (6.2), so its own sequential decision reads never wrap an L+1 ring, and the accepted top-k — resolved within the supplied stream, all fitting the ring — are guaranteed carry hits: the final loop ([diskann_core.rs:1577-1581](../../vectorlite/src/diskann_core.rs#L1577)) performs **zero** SQL reads while still charging one owner visit per call exactly as HEAD. On a carry miss (reachable only after a D6 disable), `rowid()` performs a real charged NodeIdentity read; correctness and visit totals are unaffected either way. The inline rowids returned by `need_rowid=true` batch scoring are delivered to the batch callback, which needs them for retirement and SQL-filter decisions ([diskann_core.rs:1133-1141](../../vectorlite/src/diskann_core.rs#L1133)), and are charged; they are discarded from the **carry** only, never from the callback (storing them in the carry would need scored-candidate capacity, which is unbounded). The carry is cleared at operation end. D4's prohibition is narrowed to store-level row-content reuse across reads, which the carry is not (INTEGER-only columns, operation-scoped, detector-backed).

**D6 Budget and owner arithmetic (envelopes held byte-identical; every new allocation charged).**
- **Query owner:** the owner formula and the 5-name list in `Budget::admit` are **unchanged**; the transient adjacency envelope is (16-byte copied slot blob + 8-byte streamed native id) = the existing `physical_degree * 24` term — the decoder streams one slot at a time and fills the pair cache directly, so no second full pair buffer exists, which itself covers the full per-slot peak at every legal degree up to 10,000. T1 unit-tests the envelope at maximum degree against the existing 64 KiB transient buffer.
- **Retired shape:** the load statement's `MEMUSED` plus the owned `Vec<u64>`'s `count * 8` bytes are admitted through the shared `ReaderAllowance` cursor before node readers; after the one-shot load statement drains and finalizes, the Vec's bytes stay recorded as a **non-demotable** slice of `admitted_total` so reader demotion (`demote_all`/`demote_to_admitted`) never forgets them.
- **Carry (rounds 3-4):** the ring's (L + 1) * 24 bytes plus container slack are charged as another admitted shape from the same cursor, offered **after** the retired shape and all node readers (value order: retired, then NodeExpand/NodeScore/NodeIdentity/Exact, then the carry) with non-closing decline semantics, so a very large L can never close admission ahead of the node readers; once admitted, carry bytes stay recorded as a non-demotable slice alongside the retired Vec's. When the allowance cannot cover it (tight baseline-minimum budgets), the carry is **disabled for that operation** and the final loop uses ordinary charged NodeIdentity reads (k extra reads, ~tens of microseconds; correctness and visit totals unaffected). The fixed-baseline boundary tests cover carry-on/carry-off at one byte below/at/above each T0 constant.
- **Pair cache (v12):** the per-expansion native→entry cache (one 16-byte pair per `physical_degree` slot plus fixed slack) is charged as an admitted shape **after the carry**, with non-closing decline; when it cannot be admitted it is disabled for the operation and scoring takes the charged `NodeIdentity` miss path (zero additional visits — the scored candidate's rowid+vector charges are the D5 map's charges). Admitted cache bytes are non-demotable alongside the retired Vec's and the carry's.
- **Canonical workspace floor:** the ninth layout is **excluded from the canonical floor's name fold** with a documented rationale: the retired table's writer is a per-use, non-retained statement with no per-row buffers, fitting the existing fixed 24 KiB slack, and its query-time reads are admitted from the query budget. T1 pins the floor byte-identically at the recorded boundaries — for table `"v"` (dim=2) the floor stays exactly 26,824 bytes, so `cache_bytes=24576` still rejects and `cache_bytes=27000` still accepts with the 32-row batch still rejecting.
- **`core_bytes`:** the existing formula is reused with all admitted shapes (retired, carry, pair cache, node readers) in the same cursor: when nothing is admitted `core_bytes = head`; otherwise `head - admitted_total - REPREPARE_HEADROOM`, always `>= floor` because `admitted_total <= reader_allowance <= head - floor - REPREPARE_HEADROOM`. Unit tests enumerate the combinations.
- Import (`CandidateInput::copy`) and cleanup (`cleanup_step`) per-record byte formulas are updated (`vector_bytes + physical_degree * 16` + header) with chunk-size arithmetic tests; the existing 65,536-byte step budget already forces per-call `max_records` reduction at extreme degrees under v4's 8-byte slots, and the v5 formula's test makes the reduction explicit.
- Boundary and small-budget differential tests use **fixed baseline-derived minimum budgets** captured in T0 and test one byte below/at/above those constants rather than re-deriving per-artifact thresholds.
- `cleanup_step` reclaims `generation_retired` with the same bounded discipline using the **existing PK-correlated deletion pattern** (round-3 correction: literal `DELETE ... LIMIT` requires the optional `SQLITE_ENABLE_UPDATE_DELETE_LIMIT` build feature; the repo's existing pattern selects bounded PKs and deletes by IN over them), counted against the step's `max_records`, and the generations-row delete gains `NOT EXISTS(SELECT 1 FROM diskann_generation_retired WHERE generation_id=?1 LIMIT 1)`; `x_shadow_name` and `StorageNames` register the ninth suffix, and the Python `SUFFIXES` lists follow. The bounded-GC test tuple gains `"generation_retired"` so one `max_records=1` step is asserted to bound all four tables together.

**D7 Migration (executable surface).** Connect-time behaviour is unchanged and fail-closed: opening a format-4 database rejects in `check_format()` before any mutation. The migration surface is a new scalar, `vectorlite_index_upgrade(schema, table)`, which does **not** require the vtab connection:
1. **Catalog validation:** resolves the table's declaration from the schema catalog (the `diskann_control` parse path, without the `SELECT ... WHERE rowid=-1` probe), builds the expected **format-4** descriptor, and validates the stored `v_diskann_meta` descriptor verbatim against it; anything non-canonical refuses before any mutation. A second invocation on an already-upgraded database cleanly refuses at the `format_version == 4` check with zero mutation.
2. **One transaction (SAVEPOINT wrapper, `RELEASE` on success, `ROLLBACK TO` + `RELEASE` preserving the primary error on failure), after refusing when `journal_mode=off`, when other statements/cursors are busy on the connection, or an explicit outer transaction makes the wrapper ambiguous:** drops `generations`/`graph_nodes`/`jobs`/`snapshot_map` rows and recreates `meta` with `format_version=5` and the v5 descriptor **derived by parsing the carried v4 descriptor**, preserving `revision`/`next_*`/`canonical_count`/`retired_count`/`cleanup_entry_id`/`instance_id`, setting `published_generation = NULL`, `candidate_generation = NULL`, `active_job = NULL`, incrementing `next_fence` (documented abandonment of any active/candidate job state; a bumped fence means no stale lease can reattach); then recreates the v5 shapes including `generation_retired`. `entries`/`current` are untouched. The user then republishes through the existing fenced job machinery. **Connected-instance note (round 3):** if a vtab instance for the table is live on the same connection, the upgrade still runs but that instance fails closed on its retained statements (reprepare against the new shapes errors — the class the terminal-reprepare test proves fail-closed) until reconnect; doc/diskann.md recommends upgrading before connecting. **Failure injection (T6(d)):** a progress-handler abort mid-upgrade rolls back to the SAVEPOINT with no partial DDL; a concurrent second connection's write refuses cleanly.
3. **Registration plumbing:** `lib.rs` `RegistrationCleanup.functions` grows from 9 to 10 entries with `("vectorlite_index_upgrade", 2)` in `preflight_functions` (the fixed-size array would otherwise panic — and the crate is panic-abort — on load).

Reverse-route honesty: after reverting to HEAD, a migrated database is rejected cleanly by the format check — never silently misread — and rollback states this.

## 11. Risks and mitigations

- **R1 Eligibility equivalence.** The retired table is maintained at both write sites inside the same transactions; the count invariant over existing columns is asserted at import, publication, and every operation start (active generations only); churn is bounded by per-generation retirements; whole-query fallback at every budget; three-phase churned fixtures including a tight-budget fallback cell are gated differential cells.
- **R2 B1-class reentrancy.** No store-level reuse; per-read guards; INTEGER-only carry; two-stamp detector (anchor to pre-return, all routes) with SQLITE_BUSY; the D10 matrix pins every reachable reentrancy class with a deterministic test.
- **R3 Import cost growth and chunk arithmetic.** Byte formulas updated with unit tests; worker-side resolution adds zero import SQL; measured in T7; material regressions are escalated, not hidden.
- **R4 768D page density.** Column order minimizes the local prefix (locality stated honestly in D1: the adjacency blob itself can overflow at 768D/degree-41); 768D is a gated 5% no-regression cell, so a page-density regression fails the gate rather than hiding.
- **R5 Migration.** The upgrade scalar validates the exact v4 catalog, runs transactionally with journal/cursor guards, resets the meta invariants, bumps the fence, and is round-trip tested including active-job abandonment, connected-instance behaviour, abort injection, and the documented defensive-mode behaviour (no refusal expected); reverse-route rejection is documented in rollback.
- **R6 Gate miss.** Escalate with T7 evidence; thresholds are not adjusted silently.
- **R7 Budget arithmetic.** Owner envelope and canonical floor held byte-identical with pinned boundary tests; every new allocation (retired shape, carry, pair cache) is charged through the shared allowance with disable-fallbacks and non-demotable accounting; fixed T0 constants for boundary tests; disjointness asserted over all shape combinations.
- **R8 Divergence misuse.** Every divergence class is enumerated in D10 with its detection limits (balanced substitution beyond the scored-row rule; versions the next build actually reads), pinned by tests, and surfaced at the user gate — nothing is discovered silently mid-delivery.
